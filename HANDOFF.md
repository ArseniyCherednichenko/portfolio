# portfolio — Session Handoff

> Arseniy Cherednichenko's personal portfolio site. Living context for a fresh
> Claude session (or the daily routine). Goal: grow this into a polished,
> motion-led, professional portfolio over time, applying the craft from Guided.

## Stack
React 18 + Vite + TypeScript (strict) + **Tailwind v4** (via `@tailwindcss/vite`, classes auto-detected, no content config) + **Framer Motion** for animation + **react-router-dom v6** for client-side routing. Dark theme, lime accent `#DCF87C`.

## Typography
Two faces. **Inter** (system fallback stack) carries body copy and UI. **Fraunces** — a self-hosted variable serif (`public/fonts/fraunces-latin*.woff2`, opsz 9..144, wght 300..700) — is the display face for headlines, giving the site an editorial voice instead of a templated all-sans look. `@font-face` (latin + latin-ext subsets) and a Tailwind `@theme` token `--font-display: "Fraunces", ui-serif, Georgia, serif` live in `src/index.css`; that token generates the **`font-display`** utility, and a sibling `.font-display { font-optical-sizing: auto }` rule lets the optical-size axis track the rendered size. The latin woff2 is `<link rel="preload">`ed in `index.html` so headlines paint without a flash. Apply `font-display` to display-level headings only (hero/page titles, section H2/H3, project titles, modal titles, big statement lines, ProjectPoster name); keep small labels/eyebrows/sub-card headings in Inter for hierarchy. The variable subset is weight-capped at 700 (`font-bold`).

## Architecture (multi-page)
- `src/main.tsx` wraps `<App/>` in `<BrowserRouter>`.
- `src/App.tsx` = route table only (`<Routes>`). **Routes are code-split**: `Home` is imported eagerly (it's the landing page, so it ships in the initial bundle and never flashes a loader), every other page is a `React.lazy(() => import('./pages/…'))` so it becomes its own chunk streamed in on navigation. This cut the initial JS from ~567 KB to ~380 KB (the Playground alone — which imports most of the experiment components — is now a ~64 KB on-demand chunk), and removed the Vite >500 KB chunk warning. When adding a page, follow the same `lazy()` pattern; keep `Home` eager.
- `src/components/Layout.tsx` = persistent shell (Aurora + Nav + `SiteFooter`) with `<AnimatePresence>` page transitions (keyed on pathname), a `ScrollManager` that scrolls to `#hash` targets or resets to top on navigation, a site-wide `ScrollProgress` reading bar (top edge), a `BackToTop` floating control, and a `Preloader` intro curtain mounted last (above the whole shell). The animated `motion.main` wraps the outlet in a **`<Suspense fallback={<RouteFallback />}>`** boundary so lazy route chunks resolve inside the page-transition container — the exit/enter animation still plays, and a slow chunk shows the branded `RouteFallback` (Home is eager, so the landing never triggers it). Verified at runtime with Chromium: the initial load pulls only the main chunk (no Playground code), navigating to `/playground` streams its chunk in and renders, no console errors.
- **SiteFooter** (`src/components/SiteFooter.tsx`): the global footer, mounted once in `Layout`. Replaced the old run-on paragraph of links with a proper closing statement in three regions: (1) a **CTA** — an Eyebrow + `font-display` headline with `GradientText`, a `MagneticButton` "Get in touch" into the shared contact dialog, and Email/GitHub pills (real channels only, from `data/contact`); (2) a **navigation map** — a wordmark + one-line positioning plus three grouped `<nav>` columns (The making / In words / This site), each link a `FooterLink` whose lime hairline draws in from the left on hover; (3) a **meta row** — a live Berlin clock via `useBerlinTime` with an awake/asleep dot, "Built by hand · N+ components · year" (N from `data/stats` `COMPONENT_COUNT`), and the "Press ? for shortcuts" hint. A lime bloom sweeps the top hairline once on a loop (held static under reduced motion). Guided is not named here — the footer is about the site and its maker.
- **RouteFallback** (`src/components/RouteFallback.tsx`): the calm, brief loader shown while a lazy route chunk streams in. A single lime orbit that traces itself (a rotating `border-t` arc + a pulsing centre dot, echoing the HeroOrbit / favicon mark) over a `min-h-[70vh]` so the footer never jumps up under it, with an uppercase "Loading" label. `role="status"`/`aria-live="polite"`; under reduced motion the orbit sits still (static ring + dot, no spin or pulse).
- **Preloader** (`src/components/Preloader.tsx`): a once-per-session intro curtain mounted at the top of `Layout` (`z-[200]`). On the first load of a tab it renders a dark overlay with the name, a `GradientText` counter that eases 0→100 off the rAF clock (`COUNT_MS`), and a filling lime line; when the count completes, a row of `PANELS` (6) vertical panels wipes upward in a staggered sequence (`i*0.06` delay) to reveal the site, then the component unmounts (`setShow(false)` on the last panel's `onAnimationComplete`, guarded by `leaving` so the initial mount never closes it early). Plays exactly once via a `sessionStorage` `intro-played` flag (set immediately on show, so a mid-intro navigation can't re-trigger it), and locks `body` scroll while up. Reduced-motion users are decided out **synchronously in the `useState` initializer** (`useReducedMotion()` read first), so they never see even a flash of the blocking overlay — the intro is skipped entirely. Honest brand motion, no content claims; `aria-hidden` and non-blocking to assistive tech (the real page is fully in the DOM underneath).
- **Scroll orientation system**: `ScrollProgress` (springed lime reading bar pinned to the viewport top, `useScroll`+`useSpring`), `BackToTop` (floating bottom-right control that springs in past one screenful, smooth-scrolls home), both site-wide in `Layout`; `SectionNav` (`src/components/SectionNav.tsx`) is a `lg:`-only right rail used on Home — an `IntersectionObserver` scroll-spy over the `intro/about/range/process/work/toolkit/contact` section ids that lights the active marker (spring `layoutId` ring), labels reveal on hover, click glides to the section. ### ⚠️ Push hazard — check this before pushing (a real incident happened)
The container can start with **HEAD detached** and the local `refs/heads/main`
branch pointing at a **stale/old commit** (behind the real `origin/main`). If
you then do your work in detached HEAD (after `git rebase origin/main`) and run
`git push origin main`, git pushes the **local `main` branch (the stale one)**,
**not your HEAD** — and a `--force*` will **rewind public main and destroy recent
work**. This actually happened once (main was briefly reverted 159→144, then
recovered). **Before pushing, always:**
- `git branch --show-current` — if **empty (detached)**, re-attach:
  `git checkout -B main HEAD` so the `main` branch = your work.
- Confirm `git rev-parse refs/heads/main` **equals** `git rev-parse HEAD`.
- Confirm your base matches the live remote: `git ls-remote origin main` should
  equal `git rev-parse origin/main` (proxy fetch can lag — trust `ls-remote`).
- Prefer an **explicit** push of your commit: `git push origin HEAD:main`.
- **Never** `--force`/`--force-with-lease` unless you have just proven the remote
  tip is an ancestor of your HEAD (i.e. you are strictly ahead).
